# 이미지 업로드 문제 분석 및 해결 계획

## 문제 요약

1. **사진 업로드 문제**: `/admin/artworks/new`에서 이미지 업로드가 제대로 안 됨
2. **잘못된 사진 표시**: 사용자가 올리지 않은 사진이 표시됨

## 근본 원인 분석

### 원인 1: 데이터 소스 혼재
- `src/lib/data/artworks.ts`는 **브라우저 클라이언트** 사용
- 프론트엔드 페이지(홈, 포트폴리오)에서 이 함수를 호출
- Supabase에서 `artworks` 테이블의 **모든 데이터**를 조회 (user_id 필터 없음)

### 원인 2: 다중 사용자 구분 없음
- `artworks` 테이블에 `user_id` 컬럼이 없음
- 모든 인증된 사용자가 모든 작품을 볼 수 있음
- **다른 사용자가 업로드한 테스트 데이터가 표시될 수 있음**

### 원인 3: RLS 정책
- SELECT: `USING (true)` - 모든 사람이 모든 행을 볼 수 있음 (포트폴리오 사이트라 의도된 것)
- INSERT/UPDATE/DELETE: `auth.role() = 'authenticated'` - 인증된 사용자만

## 해결 방안

### 방안 A: 단일 관리자 시스템 유지 (권장)
이 프로젝트는 **한 명의 아티스트 포트폴리오 사이트**로 설계됨.

**해결책:**
1. Supabase 대시보드에서 `artworks` 테이블 데이터 직접 확인
2. 본인이 올리지 않은 테스트/샘플 데이터 삭제
3. 업로드 기능이 정상 작동하는지 테스트

### 방안 B: 다중 사용자 시스템으로 전환
여러 아티스트가 각자 작품을 관리해야 하는 경우.

**필요한 변경:**
1. `artworks` 테이블에 `user_id` 컬럼 추가
2. RLS 정책 수정: 본인 작품만 조회/수정/삭제
3. API에서 `user_id` 필터 추가

## 즉시 확인할 사항

### 1. Supabase 대시보드 확인
- https://supabase.com/dashboard 접속
- 프로젝트 선택 → Table Editor → artworks
- 현재 저장된 데이터 확인
- 본인이 올리지 않은 데이터가 있으면 삭제

### 2. 업로드 테스트
- `/admin/login`에서 로그인
- `/admin/artworks/new`에서 이미지 업로드 시도
- 브라우저 개발자 도구 > Network 탭에서 `/api/upload` 응답 확인
  - 200: 성공
  - 401: 인증 실패
  - 500: 서버 에러 (R2 연결 문제)

### 3. R2 버킷 확인
- Cloudflare 대시보드에서 R2 버킷 내용 확인
- 실제 업로드된 파일 목록 확인
